# 06 · 参数派生与 `.hxv4p`

封包/读包都要用一组**跟游戏绑定的常量**（密钥、holder、VM 程序、盐）。
它们不是公开的，得从游戏自己的 exe 里派生出来，落到一个容器文件里复用。
本篇讲这组常量有哪些、容器怎么写、怎么组织。

## 1. 需要哪些参数

| 参数 | 大小 | 用途 |
|---|---|---|
| `HXV4_KEY` | 32 B | 映射表 XChaCha20-Poly1305 的密钥 |
| `nonce0` / `nonce1` | 24 B ×2 | 映射表解密 nonce，由描述符 `flags` bit0 选 |
| `hash_key` | 32 B | 存在 keyed `file_hash` 变体时用（实测样本 key_len 为 0，走 unkeyed）|
| `holder words` | 6 × u32 | 过滤器种子推导里的少量常量（含那个 `& (key >> 16)` 的掩码）|
| `context table` | 1024 × u32 | DRIP VM 的查表 |
| `lanes` | 128 条 | 每条是一串 `(参数, 操作码)` |
| `salt`（mediaName）| 字符串 | 两个哈希的额外输入，来自启动脚本的 bootstrap 前缀 |

外加"身份信息"：来源模块、几个 VA（manager / context / drip_impl）、派生时间等，
用于追溯与校验。

## 2. 从哪里派生

关键材料都握在游戏运行时的过滤器管理器手里。取法两条，结果等价：

- **运行时**：在游戏进程里定位管理器结构，把 key/nonce/holder/lane 读出来；
- **静态**：从 exe（及其自解密出的模块）里恢复同样的结构。

派生出来的程序与游戏版本强绑定：**游戏更新、DRIP 程序变了，参数就得重新派生**。
校验口径是"派生结果与原值一致"，而不是"看起来像"。

## 3. `.hxv4p` 容器格式

```text
+0x00  4s  magic = 'HXP1'
+0x04  u16 版本 = 1
+0x06  u16 flags（bit0 zlib 压缩、bit1 opcode 索引、bit2 RVA 归一）
+0x08  u32 存储长度
+0x0C  u32 解压后长度
+0x10  u32 CRC32
+0x14  4   保留
+0x18  ... zlib 流（解出来是下面的 chunk 串）
```

chunk 串的排布：`id u32 + 长度 u32 + 内容`，**内容按 4 字节对齐**（长度不足补齐）。

| chunk | 内容 |
|---|---|
| `0x0001` | 身份信息（来源模块路径等）|
| `0x0002` | 密钥材料：`key(32) + nonce0(24) + nonce1(24) + hash_key(32)` = 112 B |
| `0x0003` | holder words（6 × u32 = 24 B）|
| `0x0004` | DRIP 查表（1024 项）|
| `0x0005` | 128 条 lane 程序 |
| `0x0006` | 其他参数（manager / context / drip_impl 的 VA 等）|
| `0x0007` | 启动相关片段 |
| `0x0008` | 盐（mediaName，UTF-8；**空串是合法值**，所以另配一个"已知/未知"标志）|

## 4. 仓库里的组织方式

```text
<参数根目录>/
  manifest.txt                 索引：exe 摘要 → 参数摘要 → 存放目录 → 来源 → 派生时间
  <参数摘要>/profile.hxv4p     参数本体
```

用**参数摘要**（而不是 exe 摘要）作为主键：同一款游戏即使 exe 被改过几字节
（例如自己做的 crack 版），参数并没变，用 exe 摘要当主键会重复派生、重复存。

## 5. 实践注意

- **盐错了不会报错，只会"引擎看不见你的包"**：哈希全对不上，表现是静默失效。
  所以盐必须来自派生产物，不要写死默认值；
- 参数摘要与游戏版本一一对应，多款游戏并存时不要串用；
- 参数容器里同时带着"盐已知/未知"的状态位——**空串是合法盐**，
  不能拿"字段为空"当作"没记"。

## 6. 相关遗留

- `.sig` 的公钥提取与校验尚未实现（公钥嵌在 bootstrap 模块里）；
- `open_flag = 1` 那条内容层分支目前没有任何已知可用的样本，
  保留只为读老包，封包侧不要走（见 03、04 篇）。
